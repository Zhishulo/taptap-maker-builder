# 四段式迭代反馈模板

> 用法：阶段 3 每一轮需求都用这个结构。一条需求只允许一个主结果；出现「顺便 / 同时」就拆开。

~~~text
目标：【这一轮只解决什么，一句话】

现状：【现在实际是什么表现，用现象描述，不带评价】

约束：【必须保留的东西：操作方式、已确认主题、不要重构的模块、不要动的文件】

验收：【怎样算完成，写成可观察、可复现的现象】

改完后请自行构建、检查错误，并说明：改了什么、怎么验证的、验证结果如何、有没有已知遗留问题。
~~~

## 填写示例

~~~text
目标：让角色左右拖动更跟手。
现状：手指移动约 0.2 秒后角色才开始动，松手后还会滑一小段。
约束：保留屏幕下半区拖动、现有碰撞判定、Astroon 主题；不要改开始页和结束页。
验收：拖动与手指同步、松手立刻停；正常速度下不穿模；重开后行为一致。
~~~

## 检查

- [ ] 只有一条主结果
- [ ] 现状写的是现象，不是感受
- [ ] 约束具体到界面 / 文件 / 参数
- [ ] 验收可被第三方复现
- [ ] 已要求 AI 自证并说明验证结果
