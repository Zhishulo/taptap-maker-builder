## 信息时效

1. 一切以 <https://maker.taptap.cn/llms.txt> 及其链接的在线文档为准；本 Skill 只记录整理日期（2026-11-03）时的稳定结论。
2. 在线文档与本 Skill 冲突时，按在线文档执行，并在回复中说明差异。
3. 文档没有的功能、参数、模型名、价格、上限，一律不编；回答「文档没写，我去查或请以页面为准」。
4. 引用排行榜、研究所内容时给出链接与日期，别把动态数据说成固定事实。

## 成本红线

- 未经用户在对话中明确要求，不调用消耗积分的生成工具。
- 高消耗前说明：生成什么、大概多少、消耗哪类积分、有无更省的做法，然后等确认。
- 不自动替换模型或通道；换模型等于换价格与效果，属于用户的决定。
- 结果未知时标记 uncertain，先查状态，禁止盲目重投；确需重投要用户确认并说明可能已扣费。
- 详细规则见 `02-credits-and-cost.md`。

## 不可逆动作

| 动作 | 为什么不可逆 | 做之前 |
|---|---|---|
| 删除 / 覆盖素材或脚本 | 原文件可能没有版本控制 | 先备份，说明影响范围，等确认 |
| 替换模型 / 通道 | 价格与产出都变，可能已扣费 | 说明差异与费用，等确认 |
| 清空配置 / 重置项目 | 设置与绑定关系丢失 | 先导出当前配置 |
| 正式发布 | 对外可见，撤回有成本 | 逐项核对清单，等确认 |
| 批量重生成 | 大量积分消耗 | 先出一张样图，等确认 |
| 切换横竖屏 / 换主题 | 全量界面返工 | 说明哪些页面要改，等确认 |

原则：只拦「不可逆」和「属于用户的决定」；纯技术参数（抽帧张数、重试次数）不必逐项请示。

## 凭证规范

- **不回显**：不把用户粘贴的密钥、token、cookie 原文打印到输出里；必要时只显示前后各 4 位加掩码。
- **不代写**：不代替用户创建、修改或提交账号凭证；需要时指导用户在受信任的本地环境或平台设置页操作。
- **不落项目**：凭证不得写入项目文件、脚本、素材名、注释、`.env` 提交版或 Git；Maker 运行时会提交并推送整个工作区。
- **不进对话/截图**：提醒用户不要发到对话、群、截图、分享页。
- **只给可信客户端授权**：MCP 配置只接入用户自己的本地客户端；不把工具端点分享给他人。
- 本地工具若需要保存密钥，放在项目外的用户目录（如 `$DSH_HOME/...`）或系统密钥库，并确保项目目录的 `.gitignore` 覆盖临时配置。

## 原子写与文件安全

用脚本或工具写配置、台账、清单时：

1. 先写临时文件（`.tmp` / `.partial`），成功后再改名覆盖；避免构建或读取到半截文件。
2. 解析失败的文件另存为 `.corrupt-<时间戳>` 留现场，不要直接删。
3. 空值不覆盖已有值（避免保存设置时把密钥/路径清空）。
4. 覆盖前备份；批量操作先小范围试。
5. 中间产物放项目外临时目录（如 `sucai/`）并加 `.gitignore`；只把成品写进 `assets/`。

文件安全：

- 不擅自移动、重命名、删除用户文件；要动先说明并等确认。
- 不批量改写用户已有脚本的格式（会产生大量无关 diff）。
- 写入前确认目标路径是用户预期的路径，不要对计算出来的路径直接删改。

## 范围红线

- 只做策划案范围内的东西；新增系统、玩法、联网、商业化前先征得同意。
- 每个阶段确认门不得跳过；用户没确认就停在原地。
- 不擅自扩大首轮范围；想做「顺手加个排行榜」时先问。

## 协作安全

- 最多 5 名协作者（不含归属人）；协作者消耗由归属人承担。
- 协作者只能看自己创建的对话；不能发布、管理成员或转移所有权。
- 多人改同一文件可能 Git 冲突：先按功能分范围，提交前让 AI 检查工作区与最近变更。
- 添加协作者前确认对方已登录过 Maker，并核对 TapID。

## 素材与代码版权

- 外部素材只用授权允许商用的（如 CC0）；记录来源与许可证。
- AI 生成素材也要检查是否含他人 IP 元素（角色、标志、字体、音乐）。
- 参考别人工程时只学模式与结构，不整体照抄代码；注意其 LICENSE 与第三方依赖版权。
- 不使用未授权的游戏截图、影视画面、明星肖像做宣传物料。

## 发布前敏感信息检查

- 密钥、token、测试账号是否出现在代码、截图、视频、简介里。
- 内部链接、测试服务器地址、调试面板是否被录进视频。
- 是否含他人个人信息（聊天记录、手机号、头像）。
- 素材版权是否清晰；名称是否蹭知名 IP。
- 发布过的分享链接是否仍可访问、是否该关闭。

## 出事了怎么办

| 情况 | 处理 |
|---|---|
| 疑似重复扣费 | 停止重投，查任务状态与台账；拿任务 ID 联系平台 |
| 文件被覆盖 | 从备份或版本控制恢复；没有备份就停止后续写入，先留现场 |
| 凭证可能泄露 | 立即在平台侧吊销/重置，检查 Git 历史与分享页，通知用户 |
| 发布后发现阻断 bug | 优先修阻断项，重新走测试版 → 复验 → 发布 |
| 误删用户文件 | 立即停止操作，说明影响，尝试从备份/回收站恢复 |
