## 三套 UI 主题

| 主题 | 气质与适用品类 | 视觉规则 |
|---|---|---|
| **Astroon**（宇宙卡通） | 太空探索、科幻冒险、魔法奇幻；偏暗色 | 深空紫渐变背景、霓虹光晕、金色主按钮、蓝色焦点态、青色进度、胶囊按钮、圆角面板、发光与轻快动效 |
| **BrawlForge**（竞技卡通） | 竞技对战、动作闯关、派对乱斗、战斗 HUD | 亮蓝 + 紫强调色、黑色粗边框、方正硬边面板、粗体中文、生命值/能量/战斗状态专用色、强冲击力街机感 |
| **PixelForge**（像素风） | 像素游戏、复古街机、8-bit | 零圆角、2px 内描边、无模糊的硬边阴影、深色高对比、青紫高饱和、中文像素字体 |

三套主题是**视觉基线**，不是限制：定好主题后仍可继续调布局、文案、配色，但要在同一项目里保持一致。

## 怎么指定主题

在对话里直接说清「主题名 + 页面用途 + 内容」，例如：

> 用 Astroon 主题做一个开始界面：游戏标题在中间偏上，下面三个胶囊按钮「开始游戏 / 玩法说明 / 设置」，背景是深空紫渐变，主按钮金色。

要点：

- 指定主题名时用官方英文名（Astroon / BrawlForge / PixelForge），避免「科幻风」这类模糊词。
- 同时给页面层级与元素清单，比只说「做得好看点」有效。
- 主题切换属于较大视觉变更：先确认，再让 AI 改，且要求它说明哪些页面受影响。

## 主题使用纪律

- 一个项目只用一套主主题；混搭会破坏一致性。
- 换主题前提醒用户：已做的界面需要逐页调整，可能反复几轮。
- 主题不解决信息架构：按钮太多、层级混乱时先简化内容，再谈视觉。
- 涉及文字的界面要检查字号与对比度（像素风尤其容易过小）。

## 素材五类与上限

| 类型 | 单文件上限 | 格式 | 备注 |
|---|---|---|---|
| 图片 | 16MB | PNG / JPG / WebP / GIF | 不接受 AVIF / HEIC / HEIF / SVG |
| 音频 | 16MB | OGG / MP3 | 音效与 BGM 都走这里 |
| 视频 | 50MB | MP4 / WebM | 过场、宣传素材 |
| Spine | 16MB | .skel / .json / .atlas + 贴图 | 骨骼动画，可整文件夹或 zip 上传 |
| 模型 | 50MB | GLB / FBX / MDL + 配套文件 | 3D 资源，可整文件夹或 zip 上传 |

其他限制：

- 整文件夹上传或 zip 上传：单个 zip 最多 500 个可上传文件。
- 文件夹层级：从类型根目录（如 `assets/image`）往下最多再嵌 4 层。
- 搜索会跨目录匹配文件名与文件夹名。

## 上传与整理

- 支持逐张上传、整文件夹上传、zip 解包上传；对话里也能直接给图。
- 图片能力：一键抠图（输出透明 PNG）、按指令编辑、对生成结果再次生成或重新编辑；对话中的图片可标注区域再提要求。
- 命名建议：`类型_用途_序号`（如 `ui_btn_start_01.png`），全小写、无空格、无中文标点，方便脚本引用与排查。
- 大文件先压缩到上限内再传；视频不要直接传原始录屏。

## AI 生成素材的提示写法

描述里尽量包含五件事：

1. **用途**：给哪个界面/角色/道具用（主菜单按钮、关卡背景、跳跃音效）。
2. **主体与构图**：画面里有什么、主体位置、留白区域（按钮上要留文字位）。
3. **风格与配色**：与所选主题一致（如 Astroon 的深空紫 + 金色）。
4. **格式要求**：透明背景、方形/横版、成套数量、是否需要九宫格可拉伸。
5. **一致性参考**：与已有素材保持同一画风、同一光源、同一描边。

示例：

> 生成 1 张 512×512 的 PNG，透明背景，用途是 PixelForge 主题的「开始游戏」按钮底板：深色高对比、2px 青色内描边、零圆角，中间留出横向文字区。

成套素材先出 1 张确认风格，再批量生成同风格其余项。

## 边玩边下（DWP）

大资源不必等首包：运行时按需下载。常用接口（以项目内最新文档为准）：

- `cache:GetResourceAsync`：按需异步取资源。
- `cache:DownloadResource` / `cache:DownloadResources`：下载单个/多个资源。
- `cache:ObserveDownloads`：观察下载队列与进度。

注意：

- `.bin` / `.dat` / `.csv` 不会自动预加载，需要显式处理。
- 资源接口只接受 `uuid://{uuid}` 或项目虚拟路径，不要传本机绝对路径。
- 边玩边下要设计加载态与失败重试，避免玩家看到空白。

## 资源分组与预下载

预览版能力，用于控制哪些资源进首包、哪些按组预下载：

- `.project/resources.json`：`groups`（资源分组）与 `preload_groups`（预下载组）。
- `.project/settings.json`：`build.asset_ignores`（构建时忽略的资源）。

改动这些配置前先备份，并让 AI 说明会影响哪些资源；不要手写猜字段。

## 素材目录与版权纪律

- `assets/` 下任何新文件都可能被补 `.meta` 并打进构建；临时产物、抽帧、候选图放项目外的临时目录（如 `sucai/`）并加 `.gitignore`。
- 只把确认要用的成品写进 `assets/`；覆盖已有素材前先备份，属于不可逆动作。
- 外部素材注意授权：CC0/商用可用的才用；来源与许可证记在项目的素材说明里。
- AI 生成素材也要检查是否含他人 IP 元素（角色、标志、字体）。
