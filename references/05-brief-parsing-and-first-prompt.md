## 目标

把一份策划案变成两样东西：

1. 一份用户点头的「策划案理解确认单」——证明你读懂了，且没脑补。
2. 一条符合官方规范的首轮需求——能让 AI 直接开工，且只做最小可玩核心循环。

## 输入形态怎么处理

| 输入 | 处理 |
|---|---|
| 文档（docx / pdf / md / txt） | 先读全文，再抽要素；保留原文关键句作依据 |
| 图片（手写稿、截图、参考图） | 先描述图里能确认的事实，再标不确定处；不要凭画面猜规则 |
| 口述 / 长聊天记录 | 复述成结构化要素让用户确认，别直接开工 |
| 只有一句话想法 | 直接进阶段 1 的五要素提问（≤4 问），不要假装已理解 |

无论哪种输入，**都不要整段复述策划案**。用户要的是「你理解成了什么」，不是听自己的稿子。

## 五要素提取表

| 要素 | 要问清什么 | 合格标准 | 常见缺失 |
|---|---|---|---|
| 玩法目标 | 玩家要做什么？怎样算成功、怎样算失败？ | 一句话能说清目标与胜负 | 只有题材没有目标 |
| 表现形式 | 2D 还是 3D？视角？横屏还是竖屏？美术风格？ | 能画出屏幕草图 | 只说「卡通」不说视角与方向 |
| 操作方式 | 键鼠 / 触屏 / 拖拽 / 点击 / 摇杆？ | 每个核心动作对应一个输入 | 操作与玩法对不上 |
| 核心循环 | 玩家重复做的主要行为是什么？ | 一段「做 → 得到 → 变强/更难 → 再做」 | 把功能列表当循环 |
| 首轮范围 | 这一轮最需要先做出什么？ | 能在 1 个最小版本里演示 | 首轮就想做完整游戏 |

官方示例（可作为对照）：竖屏 2D 躲避游戏，拖动左右移动，躲开落物，坚持越久分越高，碰到即结束并可重开；首轮只做核心玩法 + 基础界面，美术简洁明亮。

## 提取流程

1. 通读，标出与五要素相关的原文句子（做依据）。
2. 填五要素表，每格标注 **有 / 推断 / 缺失**。
3. 「推断」与「缺失」合并成问题清单，去掉不影响首轮的问题。
4. 问题压到 ≤4 个，每个给 2–3 个候选答案。
5. 生成确认单，等用户确认后才写需求。

## 追问上限与问法

规则：**一次性最多 4 问**，每问尽量带候选答案。用户答完就动手，不要连环追问。

示例：

> 我只差 3 个点就能开工，麻烦确认：
> 1. 画面方向：竖屏（单手竖握，适合躲避/跑酷）还是横屏（双手横握，适合动作/射击）？
> 2. 失败条件：碰到落物立刻结束，还是有 3 次生命？
> 3. 首轮范围：先只做「移动 + 躲避 + 计分 + 结束重开」，还是这一轮就要加道具？

不该问的：与首轮无关的后期系统、能自己查文档的产品问题、用户已在策划案里写明的设定。

## 禁止脑补清单

以下内容**不得自行决定**，缺就标「待定」并给建议：

- 题材与世界观（科幻 / 仙侠 / 现实）
- 主角是谁、玩家扮演什么
- 核心胜负条件与失败惩罚
- 操作方式与目标平台方向（横屏 / 竖屏）
- 商业化与联网（是否要排行榜、内购、联机）
- 年龄分级与内容尺度

可以自行建议、但要在确认单里标明的：界面数量、按钮文案、占位美术风格、首轮砍掉哪些系统。

## 首轮范围怎么砍

用三问定 MVP：

1. **去掉这个，游戏还能玩吗？** 不能 → 留下。
2. **没有它，玩家能理解目标吗？** 不能 → 留下（可能只是文字说明）。
3. **它是不是只在「更好看/更耐玩」层面加分？** 是 → 放后续版本。

首轮默认砍掉：商店、成就、多关卡、剧情演出、联机、排行榜、设置项、皮肤、每日任务。

首轮必须留下：开始 → 操作 → 胜负判定 → 结束 → 重开 的完整闭环。

## 首轮需求的结构

按这个顺序写（模板见 `../assets/first-prompt-template.md`）：

1. **一句话定位**：什么设备、什么方向、什么玩法。
2. **五要素**：逐条写，一句一条。
3. **操作与胜负**：输入 → 反馈 → 判定。
4. **界面清单**：开始页、游戏页、结束页（首轮通常就这三屏）。
5. **范围外**：这一轮明确不做什么。
6. **验收**：能开始、能操作、能结束、能重开。

## 完整示例

~~~text
做一个竖屏 2D 躲避小游戏，第一轮只要最小可玩版本。

玩法目标：玩家控制小方块左右移动，躲开从上方落下的障碍，坚持越久分数越高；碰到障碍即失败，可立即重开。
表现形式：2D 俯视/正视均可，竖屏 9:16，Astroon 主题，简洁明亮，占位图形即可。
操作方式：手指在屏幕下半区左右拖动，角色跟随；不需要跳跃或按钮。
核心循环：躲障碍 → 时间越久分数越高 → 速度逐渐加快 → 碰到结束 → 重开再来。
首轮范围：只做开始页、游戏页、结束页；实现移动、落物、碰撞、计分、结束、重开。

界面：
- 开始页：标题 +「开始游戏」按钮。
- 游戏页：顶部当前分数与最高分，中间游戏区，无暂停。
- 结束页：本局分数、最高分、「再来一局」按钮。

这一轮不做：道具、音效、皮肤、排行榜、设置、多关卡、联网。

验收：能正常开始；拖动跟手；碰撞必结束；结束页能重开且分数清零；竖屏下按钮都点得到。
~~~

## 好 / 坏对照

| 坏的需求 | 问题 | 改法 |
|---|---|---|
| 「做一个好玩的太空游戏」 | 没有玩法、胜负、范围 | 按五要素补齐，先给最小闭环 |
| 「加个排行榜、商店、皮肤、联机」 | 首轮范围爆炸 | 全部移出首轮，先做核心循环 |
| 「操作手感好一点」 | 验收不可观察 | 「把拖动跟手延迟降到感觉不到；松手后立即停住」 |
| 「画面参考这个游戏」 | 可能涉及他人 IP | 描述风格与配色，不要求复刻具体角色与界面 |
| 「顺便把性能优化一下」 | 一条需求两个结果 | 拆成单独一条，先修玩法 |

## 交付前自检

- 五要素齐全，没有靠猜的关键设定。
- 首轮范围能用一句话说清「这一轮只做什么」。
- 有明确的「范围外」清单。
- 验收条目可观察、可勾选。
- 用户已确认确认单。
- 可选：用 `python ../scripts/check_brief.py brief.json` 做一次机械检查。
