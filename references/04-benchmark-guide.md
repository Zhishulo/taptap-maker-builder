## 它测什么

测 AI agent 在**真实 UrhoX 引擎**上用 **Lua** 完成游戏开发任务的能力：写或改一个功能（物理玩法、3D 场景、UI、动画、网络同步等），在带引擎文档与辅助库的工作区里完成，由引擎判定是否真的工作。

范围刻意「窄而深」：一个引擎、一门语言做透，而不是浅测多个引擎。所以它**不是**通用编程榜，也不是游戏设计能力榜。

## 三级判分：L0 / L1 / L2

| 级别 | 判什么 | 说明 |
|---|---|---|
| L0 交付物 | 是否产出了题目要求的文件 | 最基本的完成度 |
| L1 静态分析 | 代码是否通过 Lua 语言服务器检查 | 语法/类型层面的正确性 |
| L2 引擎执行 | 真实 UrhoX 无头执行 + 确定性 Lua 断言 | 校验位置、物理行为、UI 状态、网络接线等 |

**主榜头条是 L2 通过率**：代码不只是「看起来对」，而是「跑起来对」。判分回路里没有 LLM 裁判，所以分数不受裁判偏好、prompt 敏感性或文风影响。

## 榜单维度与正确读法

| 维度 | 是什么 | 怎么读 / 别怎么读 |
|---|---|---|
| L2 通过率（95% CI） | 多题多次重复的通过率，带置信区间 | 区间重叠就是没分出高低；不要只比小数点 |
| 前沿 Held-out | 题面、标准答案、运行记录都不公开的私有题；只展示分数 | 抗污染，读作「没见过的题上的泛化」；题目身份、题集规模与构成不公开 |
| Token 效率 | 每百万 output token 能完成多少次 attempt（含通过和失败） | 不是账单成本，也不是通过率；写得少不等于做得好 |
| 速度 | output token 吐字速度 | 只是生成阶段速度，不含思考与工具往返 |
| 单题耗时 | 端到端 wall-clock：推理 + 吐字 + 工具往返 | 排除 infra 超时/挂死的 attempt；是实测，不是厂商 SLA |
| 分类能力 | 按能力类别分的榜 | 当前前端开关关闭、数据不足以公开比较；不要引用具体分类名次 |
| 难度分层 | Basic / Intermediate / Advanced | 看你关心的难度档，不要只看总分 |
| 成本子榜 | 每题成本，按便宜到贵排 | **不是能力排名**；成本是刊例价估算，不是账单；未计量通道显示 N/A |
| 用量子榜 | 输出/题、轮次/题 | 不是钱，也不是通过率；很快失败、写得很少会显得「省」 |

## 统计：置信区间与名次范围

- 每个分数都是**每道题多次独立重复**的通过率；95% 置信区间用按题加权的 bootstrap 计算；当模型全过或全败、bootstrap 退化时，回退到 Clopper–Pearson 精确区间。区间宽度反映样本量。
- 每个名次带**可能范围**：对整张榜做 bootstrap（重采样测量噪声 → 重新排名 → 重复），取该模型名次的 2.5–97.5 分位。
- 例：名次数字是 3、下方标 1–9，意思是「点估计第 3，但第 1 到第 9 都与数据相容」。
- **范围重叠 = 当前样本量下先后未解析**。这时候说「A 比 B 强」是过度解读。

## 抗污染与可追溯

- 双层数据集：公开题用于难度/分类榜；held-out 私有题用于前沿榜，题面与答案永不公开。
- 数据集按语义化版本演进；每个 edition 固定引擎 commit、数据集版本与内容哈希。
- 每题有 `task_hash`、每套判分电池有 `battery_hash`；原始结果永不修改，勘误走只增台账。
- 生成阶段在每次尝试独立的硬化容器里运行，物理上读不到判分面（标准答案、断言脚本）。
- 判分 = 引擎真实执行 + 确定性断言，同一份代码重跑得到同样判决。
- 已发布 edition 永久存档，模型不会从 edition 中静默下架；模型以跑分时固定版本标识，厂商更新后需重新跑分才出现。

## 局限性

- 单引擎、单语言：结果不能直接外推到 Unity / Unreal 或其他技术栈。
- 采样方差：agent 是随机的，分数接近就应读作接近。
- 成本是刊例价估算，不是实际账单。
- 耗时是本机实测，受网络位置、脚手架与厂商负载影响；长题全挂可能显得更快。
- 每次跑分使用单一 agent 驱动：分数反映「模型 + 脚手架」的组合，换脚手架结果可能变化。

## 怎么用在你自己的项目上

- 选模型时看**难度分层 + 你的任务类型**，不要只看总分第一名。
- 看 L2 而不是 L0/L1：能跑起来比能写出来重要。
- 看置信区间决定「值不值得换」：差异落在区间内，换模型收益不明确。
- 用成本/用量子榜做预算沟通，但明确告诉用户「这是估算，不等于你的账单」。
- 引用时给出来源链接与 edition 日期，别把动态榜单说成固定事实。

## 常见误读

| 误读 | 纠正 |
|---|---|
| 「第一名就是最适合我的」 | 看难度档、类别与区间；总分高不代表你的玩法类型强 |
| 「60% vs 63%，后者更强」 | 区间重叠时无法判定；看区间与名次范围 |
| 「成本最低的性价比最高」 | 成本榜是按价格排序，不代表能力 |
| 「Token 效率高就是省钱」 | 效率是每百万 output token 的 attempt 数，含失败；不是账单 |
| 「这个榜能说明所有游戏开发能力」 | 只针对 UrhoX + Lua，且是单脚手架实测 |
| 「分数低就是模型不行」 | 可能是脚手架不匹配、任务类型偏科或采样方差 |
