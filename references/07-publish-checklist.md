## 发布前置条件

- 阶段 4 五项验收全部通过；发布前 6 项健康检查无阻断项（见 `06-iteration-and-acceptance.md`）。
- 发布面板已选择发布厂商；厂商需已完成开发者认证。多厂商时必须先选，单厂商通常自动选。
- 物料生成阶段完成，发布按钮才可用。
- 版本一致：截图、视频、封面都来自当前要发布的版本。

## 物料清单

| 物料 | 要求 | 常见错误 |
|---|---|---|
| 游戏图标 | 必需；清晰、与内容一致、缩小后仍可辨认 | 用截图硬裁、暗色图标在深色底上糊成一团 |
| 游戏截图 | 至少 3 张；展示真实玩法画面 | 用旧版本截图、只截开始页、带调试信息 |
| 宣传图 | 必需；体现核心卖点 | 文字过多、与实际玩法不符 |
| 横版封面 | 必需；适配横版展示位 | 主体被裁切、留白过多 |
| 竖版封面 | 必需；适配竖版展示位 | 直接拉伸横版导致变形 |
| 方形宣传图 | 竖屏游戏的实机视频需要 | 漏做，导致物料不全 |
| 游戏名称 | 必需；与内容一致、不蹭知名 IP | 名称过长被截断、含特殊符号 |
| 游戏简介 | 不少于 10 字；说清玩法与亮点 | 只写「好玩」「快来玩」 |
| 开发者的话 | 不少于 10 字；真诚、具体 | 复制简介、空话套话 |
| 实机测试视频 | 首次正式发布必需；真实操作录屏 | 录到调试界面、卡顿、竖屏游戏没配方形图 |

额外提醒：

- 物料尺寸、比例、格式以发布面板提示为准；不要凭别的平台经验套用。
- 竖屏游戏：视频要竖屏拍，并补方形宣传图。
- 截图与视频里不要出现账号、密钥、内部链接、他人个人信息。

## 物料生成的成本与顺序

1. 先用文字确定物料清单与每张图的构图（例如「图标：正方形，主体是角色头部特写」）。
2. 告知用户这一步会消耗积分（可能含图片与视频），等明确同意。
3. 先出 1–2 张样图确认风格，再批量生成。
4. 生成的物料要人工挑选与裁剪，不要直接全量上传。
5. 上传后在发布面板逐项核对，确认与当前版本一致。

## 发布流程

1. **核对物料**：逐项对照上表，缺项补齐。
2. **选择发布厂商**：发布面板选择已完成开发者认证的厂商。
3. **生成 / 上传物料**：确认发布按钮可用。
4. **更新测试版**：发布面板「扫码在手机上测试」→「更新测试版」→ 扫码复验。
5. **录实机视频**：首次发布需要实机测试视频；录当前测试版的真实操作。
6. **正式发布**：提交后等待任务执行；发布面板操作本身不消耗创作积分。
7. **发布后自查**：在 TapTap 打开已发布游戏，走一遍核心流程。

## 测试版二维码与版本同步

- 入口：预览工具栏「扫码在手机上测试」→「更新测试版」→ 用手机扫码。
- 二维码固定指向**测试版本**，不是当前预览里的实时画面。
- 改了代码、画面方向、项目配置或物料后，都要重新「更新测试版」，否则扫到的是旧版本。
- 出现「检测到未同步的内容修改，扫码显示旧版本」时，先更新测试版再扫码。
- 该未同步提示依据项目配置更新时间与二维码生成时间判断，**可能识别不到所有源码变化**；重要改动后一律手动更新。
- 分享链接与二维码：预览工具栏「分享」生成；单个分享链接最多 100 人访问；创建分享页前需先在发布面板选好发布厂商。已有分享版本不会自动包含后续修改，重新构建后要点「同步当前构建版本」。

## 分享页

- 用于小范围试玩与收集反馈，不消耗积分。
- 分享前确认：没有调试信息、没有未完成内容、没有敏感信息。
- 收到反馈后，回到阶段 3 用四段式需求逐条修，不要一次全改。

## 发布后

- 玩家反馈入口：TapTap 游戏菜单「问题反馈」；可按 TapID / 游戏 UID / 论坛帖子 ID 查询。
- 客户端游戏内问题回传：游戏菜单「问题回传」→ 在对话里让 AI「拉一下刚才的反馈日志」。
- 发布新版本时重复「更新测试版 → 扫码复验 → 发布」；物料有改动要同步更新。
- 线上问题优先修阻断项，再谈体验优化。

## 可复制的核对清单

~~~text
[ ] 图标已上传且缩小可辨认
[ ] 截图 >= 3 张，来自当前版本
[ ] 宣传图已上传
[ ] 横版封面已上传
[ ] 竖版封面已上传
[ ] 竖屏游戏：方形宣传图已上传
[ ] 游戏名称已填写
[ ] 简介 >= 10 字，说清玩法
[ ] 开发者的话 >= 10 字
[ ] 首次发布：实机测试视频已上传
[ ] 测试版已更新并扫码复验
[ ] 发布厂商已选择且完成认证
[ ] 物料与当前版本一致
[ ] 发布前 6 项健康检查无阻断
~~~

可用脚本做机械核对：`python ../scripts/check_publish_materials.py materials.json --root <项目根>`。
